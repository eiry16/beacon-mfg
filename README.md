## 这是什么

BeaconMFG（供应商灯塔）是一个**面向 Agent 检索**的制造业供应商名录：

- 按 **GB/T 4754-2017 国标四级归档**（门类 → 大类 → 中类 → 小类），采购口语用别名表映射到国标码
- 同时按 **GB/T 4754-2017 国民经济行业分类**给每家企业打国标小类标签（`industry` 字段）
- 每条供应商记录含：公司名、主营关键词、地区、官网、公开联系方式、资质标签、数据来源、国标行业
- Agent（WorkBuddy、GPTs、各类 MCP 客户端）加载本仓库的 `SKILL.md` 后即可按需求检索
- 数据全部来自**公开 POI 名录**（地图 / 工商公开企业黄页，public_directory），可溯源、可申诉
- **海外版**：`SKILL_EN.md` + `data/en/`（英文数据集）

## 数据就是 JSON 文件

本仓库**不依赖任何脚本或 API Key**。数据存放在 `data/` 下，是普通 JSON 文件：

```
beacon-mfg/
├── SKILL.md                    # Agent 主指令（中文数据集）
├── SKILL_EN.md                 # Agent 主指令（English / 海外版）
├── data/
│   ├── gb/                     # 中文数据：国标四级归档 gb/{门类}/{大类}/{小类}.json
│   ├── gb-index.json           # 归档主索引：四级层级树 + 各级计数
│   ├── gb-alias.json           # 采购词别名表：采购口语 → 国标小类码
│   ├── industry-index.json     # GB/T 4754 国标行业索引：代码 → 企业 ID 列表
│   ├── region-index.json       # 地区索引：城市 → 企业 ID 列表
│   └── en/gb/                  # 英文镜像（与中文同构的国标归档）
├── schema/supplier.schema.json # 数据结构定义
└── docs/                       # 贡献指南、品类规则、防抄袭策略
```

Agent 直接读取 JSON 即可检索，使用方式见 `SKILL.md` / `SKILL_EN.md`。

## 快速开始

### 给 Agent 开发者

1. 克隆本仓库：`git clone https://github.com/eiry16/beacon-mfg.git`
2. 将 `SKILL.md`（中文）或 `SKILL_EN.md`（英文）配置为 Agent 的 Skill
3. 让 Agent 读取 `data/` 下的 JSON 按关键词/地区检索

无需安装依赖、无需配置 Key、无需联网。

## 国标行业分类（GB/T 4754-2017）

每家企业带一个国标小类标签，格式：

```json
"industry": {
  "code": "3525",
  "name": "模具制造",
  "path": "C 制造业 > 专用设备制造业 > 化工、木材、非金属加工专用设备制造 > 模具制造",
  "confidence": "high",
  "source": "name"
},
"is_manufacturer": true
```

- **22898 / 23698 条已归类**，覆盖 **106 个国标小类码**（另有个别记录只精确到大类/中类，归入 `_partial.json`）；800 条未归类（公司名无行业信号，或属于本数据集不覆盖的门类）
- `confidence`：`high`=公司名直接命中、`medium`/`low`=关键词或品类兜底推断
- `is_manufacturer=false` 表示落在 **F51 批发业**（贸易/批发商，不是生产企业）
- 归类原则：**只信公司名**，搜索关键词只能补位；**宁可留空也不硬贴标签**
- **门店/配件型后缀会降权**：公司名带「经营部/商行/五金机电/模具配件」等后缀的，
  转批发业代码并标 `is_manufacturer=false`；带「配件/耗材」的置信度从 `high` 降 `medium`。
  避免「卖模具配件的门店」被当成模具制造厂（2026-09-08 修正，涉及 635 条）

## 数据来源与合规

| 来源 | 状态 | 说明 |
|---|---|---|
| 公开 POI 名录（地图 POI / 公开企业黄页） | ✅ 实际来源 | 当前数据集 100% 来自公开 POI 名录（public_directory），含企业名称、地址、公开经营电话 |
| 国家企业信用信息公示系统 | ⬜ 未实际采用 | 名义上的企业骨架来源，当前数据集未批量接入 |
| 政府名单（专精特新/高新技术企业） | ⬜ 未实际采用 | 资质标签来源，当前数据集未体现 |
| 企业官网 | ⬜ 未实际采用 | 业务联系方式来源，当前数据集未体现 |
| 展会/协会名录 | ⬜ 未实际采用 | 冷启动来源，当前数据集未体现 |
| 工商数据服务商（企查查等） | ⚠️ 黄区 | 仅人工参考，不批量抓取 |
| B2B 平台（1688 等） | ❌ 红区 | 不爬取 |

**红线：** 只发布企业公开经营信息，不发布个人隐私；每条数据标注 `source + source_url + verified_at`；
企业可提交 PR 或 Issue 更新/删除自己的信息。被 fork/抄袭的应对策略见 [docs/ANTI_COPYING.md](docs/ANTI_COPYING.md)。

## 联系方式数据策略

- **座机 / 400 / 800 / 手机号**：完整展示，无任何脱敏（来源为公开 POI 名录，企业自行公开的经营联系方式）
- 数据不做星号 / 掩码处理；如企业要求更正/删除联系方式，可通过 GitHub Issue 提出
