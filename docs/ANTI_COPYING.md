# 防抄袭 / 被复制应对策略

> 本项目采用"数据免费公开 + 生态占位"模式，**代码和数据必然会被 fork、克隆、搬运**。
> 这是开源的代价，无法避免。本文档说明：什么会被抄走、什么抄不走、以及如何应对。

## 一、会被抄走什么（接受现实）

| 内容 | 说明 |
|---|---|
| 代码 | `scripts/`、`SKILL.md`——标准库小工具，有心人 3 天可重写，**不值钱** |
| 数据 | `data/` 的 223+ 条记录——均来自公开渠道（ POI），抄的人自己也能抓 |
| 分类词典 | `data/index.json`——常识性整理，价值有限 |

## 二、抄不走什么（真正的护城河）

| 内容 | 说明 |
|---|---|
| 持续维护 | 本项目定期抓取、核实、纠错、发版——fork 拿到的是**死快照**，会随企业迁址/换号/注销而贬值 |
| 数据核实进度 | 我们的数据逐步完成官网核实（`is_template=false` 且有 source_url）；复制者拿到的永远落后一个版本 |
| 认领数据权利 | 企业认领（阶段 1 机制）沉淀在本平台；**企业不会去抄来的站点认领**——数据权利层面的护城河 |
| 品牌与生态位 | "找供应商就查 beacon-mfg"的心智、GitHub Star、社区 PR、Agent 平台收录入口 |
| 合规正当性 | 完整手机号仅通过"企业认领时自行提交"获得（合法授权）；复制者搬运脱敏数据无法提供完整服务 |

## 三、现有防护手段

1. **许可分层（已生效）**
   - 代码：MIT —— 随便用，欢迎 fork 学习
   - 数据：**CC BY-NC 4.0**（署名-非商业）—— 禁止商业用途
   - 抄的人一旦商业化（建站引流、卖数据、做 SaaS），**违反数据许可**，构成侵权

2. **数据自证**：每条记录带 `source + source_url + verified_at`，可溯源。被搬运后，我们可以对比数据指纹（ID 段、note 文案、核实日期）证明"此数据源于 beacon-mfg"。

3. **官方唯一仓库**：README 明确本项目**唯一官方仓库**地址；任何 fork 均为非官方镜像，不保证更新。

## 四、发现被抄袭/商用时的应对流程

1. **取证**：保存对方页面/仓库截图，记录其数据样本，对照本仓库 `source_url`/`note`/ID 编号段找相似证据
2. **判定**：
   - 仅 fork / 学习 / 个人使用 → **不追究**（本来就是开源目的）
   - 未署名搬运数据 → 发 DMCA 下架请求（GitHub 支持）
   - **商业用途**（付费 API、建站引流、卖数据）→ 先发函要求下架，无效则走 DMCA + 法律途径
3. **执行**：GitHub DMCA：`https://github.com/contact/dmca`（附证据：本仓库 LICENSE + DATA_LICENSE + 对方侵权链接）

## 五、反方视角（重要）

**被抄 = 模式被验证**。没人抄才说明没价值。
开源生态里被 fork 是常态，最终活下来的是原仓库（React / 各大开源项目皆如此）——因为生态、社区、更新都在原仓库。

## 六、长期策略（阶段 1 落地后自动生效）

| 阶段 | 机制 | 对复制者的影响 |
|---|---|---|
| 阶段 1 | 企业"认领/更新"入口 | 数据权利向本平台集中，复制者只能拿到旧的公开快照 |
| 阶段 2 | 增值 API / Agent 可见性服务 | 核心价值转向实时与认证，静态数据进一步贬值 |

**一句话：我们不防"复制行为"，我们让"复制的数据"迅速贬值——靠实时性、认领数据权利、生态位取胜。**
