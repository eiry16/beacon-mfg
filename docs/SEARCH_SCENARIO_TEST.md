# 端到端检索场景实测

用一条真实的采购需求，跑一遍客户 Agent 的完整链路，记录实际输出与暴露的问题。

需求：**「上海找一家做塑料机加工的厂」**

> 本文记录两轮实测。**第一轮**（2026-09-07）暴露了 4 个引擎缺陷；
> **第二轮**（2026-09-08）修完抓取侧与推断侧后复测，见第 7 节。

---

## 1. 需求解析

客户 Agent 把自然语言转成结构化查询：

| 参数 | 值 |
|---|---|
| `--city` | 上海 |
| `--proc` | cnc_milling |
| `--mat` | 塑料 |

```bash
python scripts/search_capabilities.py --city 上海 --proc cnc_milling --mat 塑料
```

## 2. 检索输出（第一轮，节选）

```
扫描 2701 条能力指纹，命中 47 家

             材料未填（无法确认是否做 塑料，需询价时确认）

...（共 47 家，匹配分全部为 20）

================================================================

⚠ 其中 47 家含未填硬指标，已标 ⚑待确认：
  这些卡片仅证明「该企业在名录中存在且名义上做此工艺」，

▶ 建议：本轮只能做「存在性发现」。若要真正的匹配，
```


## 4. 对照实验：深圳同样的需求

```
扫描 2701 条能力指纹，命中 29 家

[CN-MFG-0000305] 深圳市鑫达特五金塑胶cnc加工厂 · 深圳 · 匹配分 65
   工艺 ['cnc_milling','cnc_turning','metal_stamping','plastic_material']
   材料 ['工程塑料']
   命中原因：工艺命中 cnc_milling；同城 深圳；材料命中 工程塑料

[CN-MFG-0000059] 深圳市昊成五金机械加工厂 · 深圳 · 匹配分 20  ⚑待确认
   材料 未填
```

**排序有效**：有材料证据的 65 分排在首位，无证据的降权到 20 分但保留为候选。

### 4.1 一个反直觉的事实

深圳能出 65 分，不是因为深圳塑料厂多，而是因为那家厂**名字里写了「五金塑胶cnc加工」**
——名称自带完整证据链。上海 47 家 `cnc_milling` 里没有一家名字带塑料。

**结论：命中的质量完全取决于「信息是否恰好写在公司名里」。**
这是自动整理路线的天花板，也说明为什么必须靠企业认主来补数据。

## 5. 第一轮暴露的问题

### 5.1 材料未填被当成"不匹配"（已修，致命）

原逻辑中材料不匹配直接淘汰。但自动整理卡的**材料填写率仅 13%**
（上海 300 家中 38 家；上海 `cnc_milling` 47 家中 **0 家**）。
后果：任何带材料约束的查询都返回 0 家。

而同一函数里，公差 / MOQ / 尺寸未填时的处理是"保留 + 标注"——自身逻辑都不一致。

**修复**：未填材料 → 降权 `-25` 并标注"需询价时确认"，不淘汰。
语义：**没填材料 ≠ 不做这个材料**。只有"明确填了但不匹配"才淘汰。

### 5.2 淘汰清单全是噪音（已修）

`--show-rejected` 查上海却列出嘉兴的激光切割厂。改为只显示同城或同工艺的
最接近项，取前 15 条。

### 5.3 结果可信度不可见（已修）

新增尾部总览 + 命中项 `⚑待确认` 标记，让客户 Agent 知道这批结果能不能直接采信。

### 5.4 数据短板（数据源问题）

| 指标 | 第一轮实测 |
|---|---|
| 上海名字含"塑料/塑胶/尼龙/亚克力"的企业 | **1 家** |
| 全国材料标注含塑料的企业 | **101 家** |
| 上海 `cnc_milling` 47 家的完整度分 `sc` | **全部为 10** → 同分，排序失效 |

根因不是引擎，是**抓取矩阵里压根没有非金属关键词** —— 不是上海没有塑料厂，
是从来没抓过。

## 6. 第二轮：抓取侧与推断侧的修复

### 6.1 抓取矩阵补非金属关键词

`scripts/fetch_batch.py` 的 JOBS 增加了 7 个关键词：

| 品类 | 新增关键词 |
|---|---|
| 精密机械加工 | 塑料加工、塑胶加工、尼龙加工、亚克力加工 |
| 原材料 | 工程塑料、塑料板材、亚克力板 |

同时 `fetch_gaode_poi.py` 改为 `extensions=all`（多拿回 type/typecode/alias/tag/
website/email），并放宽 POI 类型过滤 —— 原来 `types` 限太死会漏掉大量工厂，
现在改为全召回、把噪声判断下沉到 `auto_profile` 按 `amap.type` 打分。

补抓结果：**新增 1386 条**塑料类 POI。

### 6.2 推断侧：关键词只推材料，不推工艺

新增 `KEYWORD_MATERIAL_RULES`，但加了三道闸，防止把搜索词当能力证据：

1. **工艺只信公司名**，绝不用 keywords —— 名录的 keywords 就是品类标签本身，
   拿它推工艺等于自我循环（实测把「海亚泡沫塑料」判成连接器）。
2. **关键词推材料需过名称冲突校验** —— 搜索是模糊匹配，搜「塑料加工」会返回
   「上海顺雨篷布批发」「振鸿木门木楼梯加工厂」。名称含相斥材料词（木/布/纸/玻璃…）
   或已有自己材料线索时，不贴标签。
3. **弱证据不覆盖强证据** —— 名称已推断出工艺时（confidence 非 low），
   不用关键词补材料。实测「上海精密机械制造」会被「塑料加工」搜到，
   不看名称直接贴标签，一家金属 CNC 厂就成了塑料厂。

### 6.3 指纹库的幽灵数据（已修）

L0 指纹是**追加写入**的。重复生成同一城市时，若挑选结果有变化，
新条目追加进去、旧条目不会被覆盖 —— 实测出现「上海 341 家 > 名额 300」，
总量 2742 而非 2701。

新增 `scripts/collect/reset_auto.py`：重跑前归档旧的自动整理层。
采用**整目录重命名**而非删除（2700+ 目录会触发批量删除保护，且重命名留退路）。

## 7. 第二轮复测

### 7.1 数据变化

| 指标 | 第一轮 | 第二轮 |
|---|---|---|
| 指纹总量 | 2742（含 41 条幽灵） | **2701**（9 城 × 300 + 1 样本） |
| 材料覆盖率 | 10.4% | **16.9%** |
| 上海材料覆盖率 | — | **21.3%** |
| 材料含塑料的企业 | 101 家 | **322 家** |
| 其中上海 | 28 家 | **30 家** |

### 7.2 单工艺查询仍不理想

```
$ python scripts/search_capabilities.py --city 上海 --proc cnc_milling --mat 工程塑料

扫描 2701 条能力指纹，命中 44 家
（全部匹配分 20，材料一律"未填"）
```

搜到了 44 家，但没有一家的材料标注了工程塑料 —— 全是金属 CNC 厂。
**这不是引擎问题，是需求理解问题。**

### 7.3 关键修正：塑料件主要走注塑，不是机加工

查了上海 30 家塑料企业后发现，绝大多数是**原料商**
（巴斯夫、三菱瓦斯化学、恩欣格——世界级塑料原料巨头），工艺是 `plastic_material`，
根本不做机加工。

而真正的塑料零件厂，主工艺是**注塑 / 模具**，机加工只用于治具、
绝缘件、小批量板材件。甲方说"塑料机加工"时，往往他自己也不确定该走哪条工艺。

因此给搜索加了**多工艺 OR 查询**（`--proc` 逗号分隔）：

```
$ python scripts/search_capabilities.py --city 上海 \
    --proc cnc_milling,cnc_turning,injection_molding,mold_making --mat 工程塑料

工艺条件（任一命中）：cnc_milling / cnc_turning / injection_molding / mold_making
扫描 2701 条能力指纹，命中 56 家

[CN-MFG-0002763] 上海凯发塑料模具厂 · 上海 · 匹配分 65 ⚠ 自动整理
   工艺 ['mold_making']   材料 ['工程塑料']
   命中原因：工艺命中 mold_making；同城 上海；材料命中 工程塑料

[CN-MFG-0008115] 上海升裕塑料模具成型加工厂 · 上海 · 匹配分 65 ⚠ 自动整理
   工艺 ['mold_making']   材料 ['工程塑料']
   命中原因：工艺命中 mold_making；同城 上海；材料命中 工程塑料

[CN-MFG-0006294] 上海忠宝模具弹簧有限公司 · 上海 · 匹配分 20 ⚑待确认
   工艺 ['mold_making','spring']   材料 未填
```

**上海终于出了 65 分结果** —— 工艺 + 城市 + 材料三项证据齐全。
排序依然有效：有材料证据的 65 分排前，无证据的降权到 20 分但保留。

## 8. 结论

**自动整理卡的价值仅是「存在性发现」**——回答"这个城市有哪些厂、名义上做什么工艺"，
**不具备能力匹配价值**。真正的匹配必须等企业认主补全公差 / MOQ / 交期。

三条硬约束，经过两轮实测都没有松动：

1. **不编造数字。** 硬指标（公差/MOQ/交期/产能）永远留空，
   只推"名义能力"（做什么工艺、用什么材料）。材料覆盖率 16.9% 是**诚实的结果**——
   大部分公司名里就是没有材料信息，硬贴标签才是造假。
2. **没填 ≠ 不做。** 材料未填时降权保留，不淘汰。
3. **弱证据不覆盖强证据。** 搜索关键词是模糊匹配产物，只能补位，不能覆盖名称推断。

这直接印证了冷启动策略的设计：自动整理卡是钩子（让供应商搜到自己、发现信息是平台猜的、
从而付费认主更正），不是交付物。客户 Agent 侧必须给出明确预期，
否则会把未经确认的卡片当成确认能力去下单。
