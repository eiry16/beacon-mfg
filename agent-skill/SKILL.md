# BeaconMFG 薄框架检索 Skill

## 这是什么（薄框架）

一个**只装指令、不装数据**的检索技能。外部 Agent 从 git 安装本目录后，手里只有：

- 本 `SKILL.md`（协议与流程）
- `client_search.py`（按需拉取封装，自带 UA、ETag 缓存）

**不需要 clone 整个仓库的 `data/`**（那有 ~100 MB，且每天刷新会过期）。
所有名录数据在**查询时才按国标码从 CDN 拉对应的那一个分片**，平均每次查询传输 < 1 MB。

> 与本仓库根目录 `SKILL.md`（`name: beacon-mfg`）的区别：根 SKILL 假设整库已检出、
> 直接读本地文件；**本薄框架是给「只装了技能、没装数据」的外部 Agent 用的**，
> 一切走 CDN 按需。两者检索结果同源、口径一致。

## 边界（强制）

- 只提供公开联系方式与基本信息，**不参与**询价/下单/交易。
- **不**对任何企业做推荐评级；用户要「最好的一家」→ 说明「按契合度排序，请自行核实」。
- 不编造价格、交期、产能；数据里没有的就不说。

## 数据源与必须知道的坑

**主源（CDN）**：`https://beacon-mfg.pages.dev`
**镜像兜底**（能直连 GitHub 时用）：`https://fastly.jsdelivr.net/gh/eiry16/beacon-mfg@main/` 等

⚠ **坑 1 — 必须带 User-Agent**：Cloudflare 对无 UA 请求返回 `403 error 1010`，
现象就是「源不通」。本技能的 `client_search.py` 已内置 UA，别自己用裸 `curl`/`urllib` 拉。
⚠ **坑 2 — 单桶方差极大**：分片按国标小类归档，热门小类整桶可达数 MB，冷门只几 KB。
**永远先拉 L0 指纹分片（~47KB）做筛选，再只为命中的少数企业拉 L2**，别直接拉整桶大档。
⚠ **坑 3 — 地域不在分片路径里**：分片只按「国标码」分，城市是记录内字段。
地域过滤在拉到 fp 分片后**客户端做**（按记录的 `city` 字段），对冷门小类无感、对热门大桶用「指纹优先」规避。

## 路径规则（从 manifest 定位）

`data/manifest.json` 列出全部分片（`p`=路径, `c`=国标码, `t`=类型, `h`=SHA1）：

| 类型 `t` | 路径 `p` | 用途 | 大小 |
|---|---|---|---|
| `fp` | `skills/registry/fingerprint/gb/{门类}/{大类}/{小类}.jsonl` | L0 指纹（每厂一行，筛选用） | ~47KB/小类 |
| `zh` | `data/gb/{门类}/{大类}/{小类}.json` | L1 中文完整档案（点开详情拉） | 小类~0.2–6MB |
| `en` | `data/en/gb/...` | 英文镜像 | 同上 |
| `phone` | `data/phone-index.jsonl` | 号码索引（横跨全库） | 0.7MB |

`{门类}/{大类}/{小类}` 例：`C/35/3525` = 制造业·模具制造。fp 与 zh 同结构，可互相定位。

## 查询流程（先澄清，再拉取）

**第 0 步：澄清需求**。用户只说「找个做精密件的」就先问清：
- **供应商类型** → 转成国标码（见下）
- **地域** → 城市名（如「上海」「宁波」）

需求明确前**不要盲拉**——薄框架的省流就靠这一步。

**第 1 步：类型 → 国标码**（三种来源，强度递减）：
1. 数字码直用（`3525` / `34` 大类 / `C` 门类）
2. 采购词查**别名表** `data/gb-alias.json` + `data/gb-alias-curated.json`
   （如 `CNC加工`→3484、`精密机械加工`→3484/3311、`PCB`→3989）
3. 行业名查 `data/gb4754-full.json`（GB/T 4754 全量，如「模具制造」→3525）

> `client_search.py` 自动走这条解析链；别名表有真实命中次数，按命中数降序，
> 策展层（公司名里没有的词）排后面。解析不出会如实告诉用户，不静默放宽。

**第 2 步：只拉命中的 fp 分片**（manifest 筛 `t=fp & c 前缀匹配` → 拉该 `.jsonl`）。

**第 3 步：客户端过滤 + 排序**：
- 地域：`city` 字段精确匹配（去「省/市」后缀）
- 工艺/材料：`proc` / `mat` 字段收敛
- 契合度排序：**关键词命中 > 资料完整度 `sc` > 有电话 `tel` > 凭证等级 `cl`**

**第 4 步：显示前 N + 按需拉 L2**。只把排前几家呈现给用户；
用户点开某家 → 才拉 `zh` 分片取完整档案（或 `skills/vendors/{id}/SKILL.md` 这张 L2 自述）。

## 客户端用法

```bash
# 国标码 + 城市
python client_search.py --industry 3525 --city 宁波 --limit 5
# 采购词（自动解析成国标码）+ 城市
python client_search.py --keyword "CNC加工" --city 深圳
# 工艺/材料收敛
python client_search.py --industry 3525 --city 宁波 --proc cnc_milling --mat 铝合金6061
# 拉某家完整档案(L2)
python client_search.py --industry 3525 --detail CN-MFG-0001234
# 离线读本地仓库（需 --repo 指向仓库根）
python client_search.py --industry 3525 --city 宁波 --local --repo /path/to/beacon-mfg
```

脚本自带：UA 头（绕开 1010）、ETag 缓存（二次查询命中 304 零传输）、主源失败自动切镜像、
结尾打印「本次传输 vs 全量 clone」证明按需省流。

## 覆盖范围（7 个国标门类）

C 制造业 / F 批发零售 / H 住宿餐饮 / I 信息技术 / M 科研技术 / O 居民服务 / R 文体娱乐。
具体家数每日变化，以 `data/DATA_STATS.md` 为准；某门类查不到先读 `data/gb-index.json` 的 `tree`
确认规模，别从别的门类凑近似结果。

## 呈现要求（强制）

- 返回 2–3 家最匹配，必须标注「数据来自公开渠道 + 核实日期（`verified_at`）」
- 联系方式完整展示（座机/400/手机）；缺失显示「待核实」，不编造
- 用户要法人个人信息 → 拒绝
- `industry=null` 不替它猜；`is_manufacturer=false` 提示「批发/贸易商，非生产」；`cl` 原样标注，L1 及以下说明「未经平台核验」

## 数据说明

- 当前约 5.2 万家中英文名录；已核实电话与待核实电话均为真实企业 POI，一并保留返回
- 国标归档覆盖约 107 个小类；覆盖 18 个城市（长三角+珠三角为主）
- 待核实记录也是真实企业，检索时保留并返回，不丢弃（`status="template"` 才是占位，当前 0 条）
- 企业要求更正/删除联系方式 → 引导其通过 GitHub Issue 提交
