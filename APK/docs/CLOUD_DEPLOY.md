# BeaconMFG 安卓端：云部署低成本方案

> 目标：让 APK 里的「指纹增量更新」「详情按需拉取」在**不自建服务器**的前提下跑起来，
> 且初期月成本压到 **0 ~ 60 元**。
>
> 本文只讲**数据面**（静态文件分发）。用户自己的 LLM API Key 走 BYOK 直连厂商，
> 不经过我们的任何服务器——这一点是成本能压到零的根本原因。

---

## 1. 为什么成本可以这么低

APK 需要联网的只有三件事：

| 需求 | 数据特征 | 量级（估算） |
| --- | --- | --- |
| ① 指纹增量更新 | 只读、静态、可缓存、按 ETag/SHA1 差分 | 全量 4.5 MB，日常增量 < 200 KB/次 |
| ② 供应商详情（zh 档案）按需拉取 | 只读、静态、按小类分片 | 单次 50 ~ 400 KB |
| ③ 供应商认证资料上传 | **写**操作、需要校验、需要落库 | 单次几十 KB ~ 几 MB |

**①②③ 的技术要求完全不同**：
- ①② 是纯静态分发 → 对象存储 + CDN 就够，**不需要任何计算资源**。
- ③ 是写操作 → 必须有服务端逻辑（校验 USCC、写档案、防刷），**这是唯一需要花钱的地方**。

所以正确做法是：**①② 走免费静态托管，③ 单独一个小函数/小接口**。
不要为了 ③ 去租一台 24 小时开机的服务器。

---

## 2. 方案对比

### 方案 A：Cloudflare R2 + Workers（推荐，国内访问需实测）

| 项 | 内容 |
| --- | --- |
| 静态分发 | R2（S3 兼容） + 自定义域名 + Cloudflare CDN |
| 免费额度 | 存储 10 GB / 月，Class A 写 100 万次 / 月，Class B 读 1000 万次 / 月，**出站流量完全免费** |
| 计算 | Workers 免费 10 万请求 / 天（10 ms CPU/次），Pages 无限静态请求 + 500 次构建 / 月 |
| 超出后 | 存储 $0.015/GB·月，Class B 读 $0.36/百万次；Workers 付费 $5/月含 1000 万请求 |
| 月成本 | **0 元**（我们的量远在免费额度内） |

**优点**：出站流量免费这一条对「每次 APP 启动拉 manifest + 增量分片」的场景是决定性的。
R2 上放 5 GB 数据、每天被读 10 万次，账单依然是 0。

**风险**：**国内直连 Cloudflare 的速度不稳定**，部分地区会明显变慢或间歇性不可达。
必须在目标用户所在网络下实测（移动 / 联通 / 电信各测一次）再决定。
如果实测不行，走方案 B。

**落地步骤**：
1. 建 R2 bucket `beaconmfg-data`，开启公共读（或用 Workers 做签名读）。
2. 目录按 `v1/manifest.json`、`v1/gb/<大类>/<中类>/<小类>.jsonl`、`v1/zh/...` 组织，
   与仓库 `skills/registry/fingerprint/` 结构保持一致（sync_assets.py 已按此结构导出）。
3. `manifest.json` 每个分片带 `sha1` 和 `z`（字节数），APP 端比对后只下变化的分片。
4. 绑自定义域名（如 `data.beaconmfg.cn`），开启 Cache Rules：`manifest.json` 缓存 5 分钟，
   `*.jsonl` 缓存 30 天（内容寻址，不可变）。
5. 发布流程：GitHub Actions 跑 `sync_assets.py` → `rclone sync` 到 R2。

---

### 方案 B：腾讯云 COS + CDN（国内速度稳，推荐国内首选）

| 项 | 内容 |
| --- | --- |
| 静态分发 | COS 标准存储 + 静态网站/CORS + CDN 回源 |
| 免费额度 | 新用户 COS 50 GB 标准存储（6 个月）；之后标准存储约 ¥0.099/GB·月 |
| 流量 | CDN 回源流量按量计费；COS 外网下行流量按量计费（约 ¥0.5/GB 量级，**需按官网当前单价核对**） |
| 请求 | 万次请求几分钱 |
| 月成本 | 5 GB 存储 ≈ ¥0.5；假设 100 个日活用户 × 每天拉 1 MB ≈ 3 GB/月流量 ≈ ¥1.5 ~ ¥3 |
| 预估 | **¥3 ~ ¥10 / 月**（量很小时接近 0） |

**优点**：国内访问速度和稳定性最好，控制台全中文，备案/接入流程成熟。

**注意**：
- 桶必须设为**公有读私有写**，否则 APP 拉不到。
- 必须配 **CORS**：允许 `Origin: *`，`Methods: GET, HEAD`。
- 强烈建议**套 CDN**而不是让 APP 直连 COS——直连走外网下行流量单价，比 CDN 回源贵很多，
  而且没有边缘缓存。
- 用 CDN 后要配缓存策略：`manifest.json` 短缓存（5 min），`*.jsonl` 长缓存（30 d）。

---

### 方案 C：GitHub Releases / jsDelivr（零成本验证用）

- 把每个版本的指纹包打成 `fingerprint-v<version>.zip` 传到 GitHub Release，
  jsDelivr 可直接加速 GitHub 文件：`https://cdn.jsdelivr.net/gh/<org>/<repo>@<tag>/...`
- **优点**：真的 0 元、0 运维，适合内测阶段几个人用。
- **缺点**：jsDelivr 国内也有被墙/限速的历史；单文件 20 MB 限制；Release 资产不适合高频增量更新。
- **结论**：**只作为内测兜底**，不要作为正式渠道。真要上量再迁 A/B。

---

### 方案 D：轻量应用服务器（不推荐做静态分发，但 ③ 需要它）

腾讯云轻量 2C2G（新用户有 3 个月免费试用）、阿里云轻量等，月费大致 ¥60 ~ ¥100。

**不要用它来分发 4.5 MB 的指纹**——带宽贵、单点、还要自己运维。
它的正确用途是跑 **collect.py / certification.py 那个 FastAPI server**，也就是 ③ 认证上传。

## 3. 唯一必须花钱的部分：认证上传（③）

`server/` 下的 FastAPI 提供认证申请、对话式采集、档案写入。这部分必须有服务端，
因为涉及**写**和**校验**。三个层次的选项：

### 3.1 层次一：先不部署（P1 阶段推荐）

**P1 只做「搜索 + 对话」，认证上传推到 P2。**
- APK 内置全量指纹 → 搜索完全离线可用 → 根本不需要服务器。
- 增量更新走方案 A/B 的静态托管 → 0 ~ ¥10/月。
- 认证上传暂时用**邮件/表单**人工通道（供应商把资料发到邮箱，我们后台手工建档）。

**这是最低成本路径：月成本 ≈ ¥10，且没有运维负担。**
在还没验证「有没有人愿意用这个 App 找供应商」之前，不要为认证功能付服务器钱。

### 3.2 层次二：Serverless 函数（上量后）

把 certification 的几个端点拆成 Cloudflare Workers / 腾讯云 SCF 函数：
- 按调用次数计费，没人用就不花钱。
- Cloudflare Workers 免费 10 万请求/天 → 认证这种低频操作基本免费。
- 需要配一个 KV / D1 存档案（D1 免费 5 GB、500 万行读/天）。

### 3.3 层次三：轻量服务器常驻（商业化后）

真有稳定供应商流量了，再租轻量 2C2G 跑完整 FastAPI（¥60 ~ ¥100/月），
配 COS 做附件存储、SQLite/Postgres 落档。

## 4. 推荐路线（按月成本排序）

| 阶段 | 静态分发 | 认证上传 | 月成本 | 适用 |
| --- | --- | --- | --- | --- |
| **P1（现在）** | 腾讯云 COS + CDN（或 Cloudflare R2 若实测可达） | 不部署，人工通道 | **¥0 ~ ¥10** | 内测 ~ 几百日活 |
| P2 | 同上 | Cloudflare Workers + D1 | **¥0 ~ ¥30** | 认证功能开放 |
| P3 | COS + CDN | 轻量 2C2G + COS | **¥70 ~ ¥120** | 商业化运营 |

**我的建议：P1 就用「腾讯云 COS + CDN」+ 认证走人工通道。**
理由：国内可达性不赌运气，成本在可忽略量级，且不需要维护任何服务器进程。
等真的有供应商开始提交认证了，再花那个 ¥60。

## 5. 数据面接口约定（APP 与托管源之间）

APP 只需要两个 URL，都在设置页可配置：

```
<base>/v1/manifest.json          # 分片清单：path, sha1, z, t
<base>/v1/fp/<path>              # 单个指纹分片（jsonl，gzip 可选）
<base>/v1/zh/<大类>/<中类>/<小类>.json   # 供应商详情分片（按需）
```

**更新逻辑**（见 `RemoteSource.kt`）：
1. 带 `If-None-Match` 请求 `manifest.json` → 304 直接结束，0 流量。
2. 200 则逐分片对比本地记录的 `sha1` → 只下载变化的分片。
3. 下载后校验 SHA1，一致才覆盖本地副本并记账；不一致丢弃并告警。
4. 检索时优先读「已更新副本」，读不到回退内置 assets。

**缓存策略**（CDN 侧）：
- `manifest.json`：`Cache-Control: public, max-age=300`（版本文件必须能快速生效）
- `*.jsonl` / `*.json`：`Cache-Control: public, max-age=2592000, immutable`（内容寻址，永不变更）

## 6. 成本护栏

- **APP 端**：manifest 请求带 ETag，且默认**每天最多检查一次**（可在设置页手动触发）。
  避免用户反复切前台造成请求放大。
- **分片粒度**：103 个指纹分片按 GB 小类切，单个平均 46 KB，
  一次增量通常只涉及几个小类 → 增量流量极小。
- **详情按需**：`zh` 档案不预置进 APK，只在用户点开某个供应商时按小类下载并缓存。
- **异常兜底**：CDN 挂了 → APP 用内置数据继续工作，只是数据不新鲜。
  这条是我们的优势：**离线可用是设计前提，不是降级方案。**

## 7. 上线前检查清单

- [ ] 目标网络实测 CDN 域名可达性（移动/联通/电信）
- [ ] CORS 规则已配（GET/HEAD，Origin 允许）
- [ ] `manifest.json` 短缓存、`*.jsonl` 长缓存已生效（用 `curl -I` 两次确认 `Age` 增长）
- [ ] SHA1 校验在真机上跑通（故意传坏文件验证会丢弃）
- [ ] 断网情况下 APP 搜索功能正常（内置数据兜底）
- [ ] 监控：CDN 流量告警阈值设为 50 GB/月（超出说明有异常刷量）
